# 按模型统计 API 调用费用

## 1. 目标与参考结论

在当前版本上完善费用统计：**每次调用记录当时单价，首页按模型汇总费用，展开比较供应商，支持公开价目自动同步和自定义覆盖。**

已确认的选择：

- 首版计算输入、输出、缓存读取、缓存写入四项费用，统一标注“估算费用”。
- 默认每 6 小时同步公开价目，也可手动刷新；自定义价格始终优先。
- 历史保留调用时价格，首次补价的历史记录标记为“历史估算”。
- 扩展首页、调用页、设置页。

参考来源已核实：CC Switch 当前从 [`models.dev/api.json`](https://models.dev/api.json) 获取模型价格，读取 `cost.input/output/cache_read/cache_write`；最新源码由后端复用代理客户端拉取。可以借鉴其数据源、四项费用明细和同步状态展示。[价格转换源码](https://github.com/farion1231/cc-switch/blob/main/src/lib/modelsDevPricing.ts)、[后端拉取源码](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/services/model_pricing.rs)

models.dev 是社区维护的公开模型数据库，价格以 USD／百万 Token 提供。因此页面称为“公开参考价”，供应商实际成交价通过自定义覆盖填写。[数据源说明与字段定义](https://github.com/anomalyco/models.dev#api-reference)

## 2. 当前结构与目标结构

当前费用由前端用全局统一单价计算，调用记录没有保存单价和费用；改价会改变历史展示结果。另一个问题是 `model_hash` 包含 Key 和显示名，更新配置后，旧调用可能失去配置关联。

```text
D:/github_project/cursor-byok/
├── server/src/provider/       # 已有：记录每次上游调用和实际用量
├── server/src/store/          # 已有：保存调用，按时间和配置模型汇总 Token
└── apps/desktop/src/features/ # 已有：首页按统一单价估算，设置页编辑统一价格
```

目标职责：

```text
D:/github_project/cursor-byok/
├── server/src/pricing/        # 新增：价目同步、来源匹配、用量计价
├── server/src/store/          # 扩展：价目、覆盖配置、调用价格快照及费用聚合
├── server/src/control/        # 扩展：价目管理和费用统计 HTTP 接口
└── apps/desktop/src/features/ # 扩展：首页模型汇总、调用明细、设置页价目管理
```

- 将首页费用计算移入后端，前端只展示结果。
- 用模型价目管理替换全局统一单价配置，删除旧类型、旧接口和前端计算逻辑。
- 在现有迁移序列后追加数据库变更，保留调用历史；旧全局单价不套用到各模型。

完整执行路径：

```text
models.dev ──启动检查／6 小时循环／手动刷新──> 后端价目同步
                                                   │
                                        SQLite 本地价目
                                                   │
Cursor／外部 API／插件调用                           ▼
       └──> 解析实际上游模型 ──> 选择公开价格或自定义覆盖
                                      │
                               调用开始：保存价格快照
                                      │
                               用量到达：更新费用
                                      │
                               调用结束：保留结果
                                      │
                         SQLite 聚合 ──> 首页／调用详情
```

同步任务归应用服务持有，随服务关闭取消；模型调用只读本地价目，不等待联网。

## 3. 计价、归属与历史规则

**归属与匹配**

- 供应商模型以“上游请求端点＋原始模型 ID”作为统计键；插件使用已有的插件／供应商／模型身份。Key、显示名和 `model_hash` 不参与费用归属。
- 模型层按实际上游 `model_id` 汇总，展开后按供应商模型分别展示。首版不自动合并不同模型别名。
- 公开价目保留完整的“来源供应商＋模型 ID”。优先按来源端点和模型精确匹配；无法确定来源时，仅在模型精确对应唯一标准模型时自动绑定，其余由用户选择。
- 不通过删除日期、截断后缀或模糊匹配强行定价。

**四项计算**

```text
估算费用 =（非缓存输入 × 输入单价
          ＋输出 × 输出单价
          ＋缓存读取 × 读取单价
          ＋缓存写入 × 写入单价）÷ 1,000,000
```

- 统一处理协议口径：OpenAI 输入扣除已包含的缓存部分；Anthropic 输入直接视为非缓存输入；插件沿用现有输入包含缓存的约定。
- reasoning Token 不在输出之外重复收费。
- 单价使用十进制计算，费用以纳美元整数保存，接口以十进制字符串返回，避免浮点累计误差。
- 用量不完整或实际使用的 Token 类别缺少价格时，费用保持未知，分别显示“用量不完整”“未定价”；免费价格明确保存为零。
- 有完整用量的失败、取消调用也计费；重试、压缩、子任务按实际调用逐次统计，避免再累加运行级用量。
- 首页正式汇总排除进行中调用；进行中的调用详情可展示暂计费用。

**价格生命周期**

- 调用开始时冻结价格来源、四项单价和时间；用量更新始终使用该快照。
- 同步或手动改价只影响后续调用，自定义覆盖不被同步覆盖。
- 首次升级及新增有效定价后，后台分批补算尚未计价的已结束调用，记录补价时间并标记“历史估算”；重复执行不改变已有结果。
- 改名、换 Key、删除模型配置均保留历史归属及费用。
- 缺价、联网失败不阻断模型调用；保留最近一次成功同步的数据和错误状态。

## 4. 接口与页面变化

管理接口继续使用现有 `/__byok-api__/api` HTTP 边界。

| 接口／类型 | 变化 |
|---|---|
| `/pricing/catalog` | 查询本地公开价目，支持供应商和模型搜索 |
| `/pricing/models` | 查询、保存模型来源绑定与自定义四项单价；清除覆盖后恢复公开价 |
| `/pricing/sync` | 查询同步状态、修改自动同步开关、手动触发同步 |
| `/overview` | 增加费用总计、费用趋势、模型及供应商分组、未计价数量 |
| 调用列表／详情类型 | 增加费用状态、价格快照、四项费用及补价标记 |

概览筛选改用统计模型键，覆盖仍在配置和已删除的历史模型，继续复用现有 `ModelSelect` 展示组件。所有费用、Token、分组和趋势使用相同时间范围及筛选条件。

页面安排：

- **首页**：将“价值估算”改为“估算费用”；现有趋势图支持 Token／费用切换；增加模型汇总表，展示调用数、四类 Token、已计价费用、平均调用费用及未计价数量。展开供应商后展示对应统计。平均费用只使用已计价调用。
- **调用页**：增加费用列；详情展示四项 Token × 单价、费用合计、价格来源和计价时间。小额费用使用足够小数位。
- **设置页**：替换原统一单价卡，管理模型来源绑定、自定义价格和恢复公开价；提供自动同步开关、立即刷新、最近成功时间及失败信息。
- 同步由后端复用现有代理网络层执行，后台与手动任务互斥；设置页列表使用现有虚拟化组件，新增文案完整支持中英文。

## 5. 实施顺序与验收

按完整链路逐层交付：

1. **计价闭环**：价目与覆盖存储、调用价格快照、四项计算、调用详情。
2. **分模型统计**：后端聚合、首页模型／供应商表、费用趋势与历史筛选。
3. **公开价目同步**：models.dev 接入、来源绑定、后台同步、历史补价和状态展示。

重点验证：

- 不同模型价格不同，同名模型的不同供应商可独立覆盖；模型汇总等于供应商明细之和。
- OpenAI、Anthropic、插件缓存口径正确，reasoning 不重复计费；原生外部 API 转发同样记账。
- 改价前后的调用分别使用各自快照；并发同步、改价不会改变进行中调用的单价。
- 换 Key、改名、删除配置后仍可查询历史；补价幂等，免费与未知费用明确区分。
- 离线、代理、超时、异常价目和重复刷新均不影响模型调用；清除请求详情保留费用。
- 新库初始化、现有数据库升级及 API／前端类型一致；运行服务端测试、前端 `npm run check` 和桌面调试构建。

首版固定 USD，采用基础四项参考单价；长上下文阶梯、不同缓存时长、快速模式加价、套餐余额和账单对账不纳入本次范围。Cursor 官方透传记录缺少可计价用量时显示未知，不并入 BYOK 费用。
