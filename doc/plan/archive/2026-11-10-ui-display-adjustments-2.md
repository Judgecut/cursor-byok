# 外观调整2

记录日期：2026-11-10。状态：已实施并归档（2026-11-11）。

本计划补充[界面显示调整计划](2026-11-10-ui-display-adjustments.md)，记录后续各窗口、各页面统一采用铺满可用区域的布局要求，以及调用分页默认值和主页自动刷新设置。

## 1. 问题与目标

用户截图中的调用页面在窗口最大化后，表格仍集中在中间，两侧留白明显过宽，未充分利用窗口空间。

- 各页面内容随窗口尺寸扩展，铺满扣除侧栏、窗口栏和适度边距后的可用区域；不再按固定最大宽度居中展示整页。
- 可以留边，但边距应是稳定、适度的界面间距，不随窗口变宽而形成大面积空白。
- 以当前共享的 `18px` 页面边距作为实施起点，常规窗口每侧控制在约 `16–24px`；窄窗口可适度缩小。具体视觉效果在实施时验证，不新增用户配置。
- “铺满”指页面容器利用可用宽高；表单字段、正文行和按钮仍按内容需要安排，不通过拉大字号、行高或无意义间隔填充空间。
- 默认窗口、手动缩放、最大化和恢复窗口均使用同一套自适应规则；后续新增页面沿用该规则。

## 2. 当前结构与限制

以下为仓库当前结构，路径均相对于 `apps/desktop/src/`：

```text
shell/                                     # 主窗口框架与页面空间分配
├── AppLayout.module.scss                  # 定义 1280px 页面宽度上限，操作区按该宽度居中对齐
└── layout/                                # 共享页面容器与虚拟滚动布局
    ├── PageLayout.module.scss             # Header、内容区、Footer 的高度分配
    ├── PageContent.module.scss            # 固定内容区受最大宽度限制，标题沿用居中偏移
    └── VirtualPage.module.scss            # 滚动内容区受最大宽度限制并居中
features/                                  # 各业务页面与独立详情页面
└── calls/                                 # 调用列表和详情
    └── CallDetailsPage.module.scss        # 独立详情页也引用页面最大宽度变量，需单独检查
```

`AppLayout.module.scss` 当前定义 `--app-page-max-width: 1280px`，共享内容容器引用它限制宽度；标题的 `left` 和操作区的 `right` 也通过同一宽度计算居中偏移。因此只修改调用表格自身宽度不能解决所有页面的留白和对齐问题。

## 3. 覆盖范围与目标行为

| 页面／窗口 | 路由 | 后续布局要求 |
| --- | --- | --- |
| 数据概览 | `/` | 统计卡片、趋势图、日历和页签表格利用可用宽度，按空间调整排列 |
| 调用详细统计 | `/calls` | 表格铺满内容区宽高，分页区域保持可见，增加窗口宽度即可增加列的可用空间 |
| Cursor 模型配置 | `/harness/cursor` | 页面和配置卡片铺满，字段按合理分栏或布局组织 |
| 插件配置 | `/plugins` | 插件列表、卡片和空态容器随可用区域扩展 |
| 系统设置与教程内容 | `/settings` | 设置分组利用可用宽度，长说明保持可读性；教程随实际承载页面一起检查 |
| 独立调用详情 | `/calls/:callId` | 浏览器打开的详情同样随窗口铺满，长请求、响应及诊断内容不得撑出页面边界 |

弹窗、菜单、提示等浮层保留符合其操作规模的尺寸，不将页面铺满要求机械应用于所有浮层；其位置和最大尺寸仍需适应窗口。

目标布局与控制流：

```text
窗口尺寸变化 / 最大化 / 恢复
  -> 主窗口框架扣除窗口栏、固定侧栏及底部固定区域
  -> 共享页面容器使用剩余宽高，左右保留统一小边距
     ├── 标题与页面操作区：对齐内容左右边缘，窄窗口下操作仍可达
     ├── 固定列表页面：表格占满剩余高度，分页保持可见
     └── 滚动页面：内容铺满宽度，仅内容视口进行纵向滚动
          -> 卡片重新排列 / 表格列分配宽度 / 图表按容器尺寸重绘

独立详情窗口尺寸变化
  -> 详情页面直接使用窗口可用宽高与统一边距
  -> 请求、响应、诊断区域随容器扩展
```

铺满布局调整由布局层负责空间分配，各业务页面负责内部排列；布局本身不新增持久化设置，不改变数据查询、筛选、分页和详情加载逻辑。第 3.1、3.2 节分别补充分页默认值和可保存的刷新间隔。窗口缩放发生在同一页面生命周期内，不应重建页面或重置筛选、页签、编辑内容和滚动位置。

### 3.1 调用列表默认每页 100 条

- 用户补充：截图中调用页面底部的每页条数默认由 `20 条/页` 改为 `100 条/页`。
- 首次进入调用页面、没有用户主动选择每页条数时，分页控件和实际列表请求均使用 `100`；保留手动切换每页条数的能力。
- 只调整调用列表的默认每页条数，不将 `100` 作为调用总数上限；总条数和总页数仍按当前筛选结果计算，例如共 200 条时默认显示 2 页。

### 3.2 主页自动刷新间隔可设置，默认 30 秒

- 概览主页增加定时自动刷新，默认每 `30 秒` 刷新一次；在系统设置中提供“主页自动刷新间隔（秒）”，支持用户输入正整数秒数。
- 设置保存后立即生效，重启后恢复；尚未设置时使用 `30 秒`。空值、零、负数和非整数不得保存，显示明确的校验提示。
- 自动刷新更新当前时间范围、供应商及模型筛选下的统计卡片、趋势图、日历和当前页签数据；调用记录使用当前分页，不自动跳回第一页。相对时间范围在刷新时随当前时间推进，用户选择的固定时间范围保持不变。
- 保留手动刷新和筛选变化触发的刷新；定时刷新沿用主页的数据加载与统计口径，不每隔一段时间刷新模型、插件等无关的全局数据。
- 仅在主页处于当前路由且窗口内容可见时运行定时刷新；离开主页或窗口隐藏时暂停，返回主页或重新可见时刷新一次，再按设置间隔继续。仅失去焦点但仍可见时不暂停。
- 定时器由主页生命周期管理；页面保活不代表主页仍处于当前路由。修改间隔时替换原定时器，离开或卸载时清理，不累积重复定时器，不补发后台错过的刷新次数。
- 上一次请求未完成时不叠加同类自动刷新；自动、手动及恢复可见触发应合并重复请求。切换筛选后的旧响应不得覆盖新结果；刷新失败保留上次成功数据并提示，下次按正常间隔重试。
- 自动刷新不清空现有内容，不重置筛选、页签、分页、展开状态或滚动位置，避免每 30 秒闪屏或打断查看。

职责与运行路径（以下为待实施安排，路径相对于 `apps/desktop/src/`）：

```text
features/settings/SettingsPage.tsx          # 编辑并校验主页刷新间隔
  -> shared/store/appStore.ts              # 保存间隔、启动时恢复并通知主页
  -> features/home/HomePage.tsx            # 根据当前路由和窗口可见性管理唯一刷新循环
       -> 现有主页查询                     # 携带当前时间范围、筛选与分页，合并重复请求
       -> 现有管理 HTTP API                # 读取统计结果，不修改历史数据
       -> 主页卡片、图表和当前页签          # 原位更新；失败保留上次成功结果

离开主页 / 窗口隐藏 -> 暂停循环
返回主页 / 恢复可见 -> 刷新一次 -> 按已保存间隔继续同一主页的数据更新
```

## 4. 实施范围与顺序

1. 调整 `shell/AppLayout.module.scss`、`shell/layout/PageContent.module.scss` 和 `shell/layout/VirtualPage.module.scss`：移除整页固定最大宽度及其居中偏移，统一使用可用宽度和页面边距，标题、操作区、固定内容与滚动内容保持对齐；删除失去用途的宽度变量及引用。
2. 按第 3 节逐页检查内部布局：移除阻碍整页展开的局部宽度限制，保留字段、正文、按钮等必要的内容尺寸约束；表格按列内容合理分配宽度，宽窗口优先展示更多列，窄窗口仅在表格内部横向滚动。
3. 调整 `features/calls/CallDetailsPage.module.scss`，检查独立详情入口的样式作用域，不依赖仅在主窗口框架内定义的变量；统一边距规则并验证长内容。
4. 检查虚拟列表和图表在连续缩放、最大化与恢复时的测量更新，确保已有容器尺寸监听正常工作；保留共享 `PageLayout`、`PageContent`、`VirtualPage` 的职责边界。
5. 将调用列表默认每页条数调整为 `100`，同步检查分页控件、请求条数和总页数计算。
6. 按第 3.2 节在设置页增加主页自动刷新间隔，复用共享状态的现有本地偏好保存方式；主页接入默认 `30 秒` 的刷新循环，验证可见性、请求合并和状态保留。
7. 完成各页面的窗口尺寸、视觉和自动刷新验收，再运行前端检查和桌面调试构建。

模块变动：修改现有共享布局和需要适配的页面样式，以及调用分页默认值；设置页、共享状态和主页增加刷新间隔配置、保存与调度，补齐中英文等现有语言目录；删除旧整页最大宽度规则及相关居中计算；不新增页面壳，不移动、合并或拆分业务模块。

## 5. 验收

- [ ] 第 3 节所有页面均已检查，最大化时内容铺满可用区域，不再出现截图中因固定最大宽度形成的宽大左右空白。
- [ ] 常规窗口左右边距约为 `16–24px`，窗口变宽时边距不随剩余空间持续增长；标题、操作区、卡片及表格边缘对齐。
- [ ] 在应用允许的最小窗口、常用 `1280×800`、`1920×1080` 和接近截图的 `2523×1378` 窗口下检查，并覆盖系统显示缩放后的有效可用尺寸。
- [ ] 表格占满可用区域，窄窗口下列内容可横向访问，分页、刷新和筛选仍可操作；页面根节点不产生横向滚动。
- [ ] 调用列表默认显示 `100 条/页`，实际请求与控件一致；共 200 条时显示 2 页，不足 100 条时显示实际记录数，仍可手动切换每页条数。
- [ ] 主页未配置时默认每 `30 秒` 自动刷新；修改为例如 `60 秒` 后立即按新间隔运行，重启仍保持，非法输入不能保存。
- [ ] 离开主页或窗口隐藏时暂停，返回或恢复可见时仅刷新一次并恢复循环；页面保活、重复切换及修改间隔不增加定时器数量。
- [ ] 自动刷新沿用当前筛选和分页，各统计区域同步更新；相对时间范围随时间推进，固定时间范围不改变，手动刷新仍可用。
- [ ] 慢请求、快速切换筛选、手动与定时刷新同时触发时，无重复并发刷新或旧响应覆盖；失败保留已有数据并按正常间隔重试。
- [ ] 自动刷新不闪屏，不重置页签、分页、展开状态和滚动位置，也不触发无关模型、插件数据的全局刷新。
- [ ] 概览卡片、图表和页签表格同步适应宽度，无裁切、重叠或图表保留旧尺寸的问题。
- [ ] 设置与配置页面利用可用宽度，同时保持输入、说明和操作之间的清晰关系；空态和少量数据时容器尺寸仍正确。
- [ ] Header、Footer 和侧栏保持原有固定职责，仅内容视口纵向滚动，标题与操作区预留空间正确，窗口控制按钮不被遮挡。
- [ ] 独立调用详情在宽窄窗口均适配，长请求、响应和诊断信息可完整查看。
- [ ] 连续缩放、最大化、恢复不重置当前筛选、页签、编辑内容和滚动位置；中英文及深浅主题下均无异常。
- [ ] 实施后在 `apps/desktop` 运行 `npm run check` 和 `npm run tauri:build -- --debug --no-bundle`。
