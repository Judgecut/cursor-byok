# 统一模型输出速度与首 Token 显示

记录日期：2026-11-10。状态：已实施并归档（2026-11-11）。

## 1. 当前问题与目标

当前模型测试使用“输出 Token ÷ 总耗时”，包含等待时间；显示为“首字”的实际是首个有效响应，可能包含空事件或控制事件。调用列表尚无速度列，外部 API 原生转发缺少首输出计时。

本计划覆盖模型测试、调用列表／详情，以及费用计划中的模型／供应商汇总表。统一展示平均生成速度和首 Token 等待时间，将速度放在靠前的位置，方便直接查看。

参考 CC Switch 的生成速度计算、短样本过滤、估算标记和按总生成时间汇总的方式：[计算与显示源码](https://github.com/farion1231/cc-switch/blob/main/src/components/usage/format.ts)、[汇总源码](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/services/usage_stats.rs)。

| 场景 | 显示 |
|---|---|
| 有有效测量 | `94 tok/s` |
| Token 或计时口径存在估算 | `≈94 tok/s` |
| 样本不足、缺用量或无法计时 | `—` |
| 首 Token 等待时间 | `1.3s` |

速度 ≥1 时取整数，小于 1 时保留一位小数；详细计算依据放入提示和详情。“首 Token（s）”表示首次实际输出的等待时间，单位为秒。

## 2. 列表布局与展示顺序

调用列表删除原来的“耗时、TTFB、TTFR、TTFT”四个独立列，改为“平均速度（tok/s）、首 Token（s）”两列。原始耗时和计时指标继续保留在调用详情。

新列放在“思考强度”之后、“Fast”之前，平均速度在首 Token 前面，使用如下顺序：

```text
状态 → 显示名称 → 时间 → 模型名称 → 思考强度 → 平均速度（tok/s）→ 首 Token（s）→ Fast → 调用类型 → 路由 → Finish Reason → 其余现有列 → 操作
```

- 平均速度和首 Token 使用紧凑列宽，不需要横向滚动到原计时列的位置才能查看。
- 模型测试的紧凑结果和详情同样优先显示平均速度，再显示首 Token；例如 `94 tok/s · 首 Token 1.3s`。
- 模型／供应商汇总表也将平均速度放在首 Token 之前。
- 未知值统一显示 `—`；估算值加 `≈`，并在提示中说明原因。

## 3. 统一计算口径

```text
请求开始 ──等待──> 首个实际输出 ──持续输出──> 调用结束
        首 Token 等待          生成时间

单次平均速度 = 输出 Token ÷ 生成时间
模型平均速度 = Σ有效样本输出 Token ÷ Σ有效样本生成时间
```

- 首个实际输出包括非空正文、思考内容、工具名称或参数；排除响应头、心跳、空增量、Usage 和纯控制事件。
- 界面“首 Token”指首个实际输出，提示说明包含思考和工具输出；详情保留现有 TTFT 正文首字、TTFR 有效响应指标，明确区分。
- 输出使用上游 `output_tokens`，不额外累加已包含的 reasoning Token。
- 速度样本要求调用成功、流式输出、输出不少于 100 Token、生成时间不少于 100ms。
- 模型首 Token 等待时间取成功流式调用的中位数；首 Token 统计不受输出 100 Token 门槛限制。
- 模型速度按分子、分母分别累加，不能平均各调用的 tok/s；并发调用各自计时。
- 模型测试独立展示结果，不混入业务调用的速度样本；其消耗仍按费用计划统计。
- 非流式、失败、取消、进行中及缺少可靠计时的调用不计算平均生成速度，速度列显示 `—`，提示具体原因；存在可靠首 Token 计时的调用仍可展示其等待时间，首 Token 缺失时显示 `—`。

`≈` 的使用依据：

- 模型测试缺少上游 Token 数、使用现有文本估算时，加 `≈`；估算 Token 不写入计费用量。
- 已知存在隐藏思考 Token，但未观察到对应输出事件时，加 `≈`。
- 测量值和估算值分别聚合；模型行优先显示测量值，仅有估算样本时显示 `≈`，提示两类样本数量。

## 4. 采集、接口与模块边界

目标职责：

```text
cursor-byok/
├── server/src/provider/       # 统一记录首输出、思考输出和调用结束计时
├── server/src/api/byok/       # 原生转发观察流式事件，补齐相同计时
├── server/src/model/          # 统一速度规则、测量状态和结果类型
├── server/src/store/          # 保存计时依据，按模型与供应商聚合样本
├── server/src/control/        # 测试和统计接口返回统一结果
└── apps/desktop/src/          # 测试、调用、模型汇总共用显示组件
```

- 新增独立的首输出延迟与流式属性，保留现有 TTFR、TTFT 的语义。首输出和总耗时使用同一调用的单调时钟。
- 原生转发在观察到事件时立即记录时间，继续原样转发响应；不能等流结束后再记录首输出。
- 模型测试复用调用记录中的计时与统一计算函数，移除当前独立的“输出／总耗时”算法。
- 数据库追加前向迁移；历史记录的新计时信息保持未知，不根据旧 TTFR 或请求正文猜测补值。
- 采集不依赖详细日志开关；清除请求、响应详情后仍保留速度所需的数据。
- 调用列表／详情和模型测试结果增加统一性能结果：速度、测量／估算／不可用状态、原因、首输出延迟及生成时间。无有效速度返回 `null`。
- 模型／供应商统计返回测量与估算各自的输出总量、生成时间、样本数，以及首 Token 等待时间中位数。
- 模型测试提示展示首 Token、生成时间、总耗时、输出数和估算原因；样本不足仍显示测试通过。
- 调用详情展示公式及不可用原因；前端共用格式化与提示组件，新增中英文文案，计算和样本筛选由后端负责。
- 模型汇总与费用计划共享模型归属、供应商展开和时间筛选，在同一张表展示费用、平均速度和首 Token；支持速度排序，未知值排最后。

## 5. 实施顺序与验收

1. 完成计时采集、持久化和统一计算。
2. 更新模型测试、调用列表与详情，落实靠前的双指标列顺序。
3. 与费用计划共同交付模型／供应商汇总表。

重点验证：

- 输出 1,000 Token、总耗时 12 秒、首输出等待 2 秒，平均速度为 100 tok/s。
- 100 Token、100ms 边界正确；短输出、零耗时、缺失字段不产生异常高值或 `Infinity`。
- 心跳、Usage、空事件不提前触发计时；思考、工具调用和正文均覆盖。
- 不同长短调用按总量汇总，首 Token 正确取中位数；测量与估算不混算。
- OpenAI Chat、Responses、Anthropic、插件及外部 API 原生流式转发口径一致。
- 测试通过与速度可用性独立；历史记录、非流式和异常调用的速度正确显示 `—`。
- 调用列表在“思考强度”之后、“Fast”之前展示“平均速度、首 Token”，原来的四个计时列已从列表移除，详情保留原始指标。
- 运行相关服务端测试、前端检查和桌面调试构建，并验证中英文、排序、提示及常用窗口宽度下的列可见性。
